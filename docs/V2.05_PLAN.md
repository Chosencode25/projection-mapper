# v2.05 — Music and Show Transport

Planning draft, November 8, 2026. The next implementation milestone is v2.05. Keep the v2.03 and v2.04 milestone numbers and defer native USB-DMX, Arduino output and physical projector/optical acceptance until the equipment is available. Build and verify v2.05 using Mac audio, Test Mode and the existing simulated fixtures.

**First rehearsal goal:** Import one song into the existing lighting rehearsal, see its waveform on the bottom timeline, and watch the projection and simulated fixtures follow the song when playing, scrubbing and repeating a section.

## 1. Add a song and waveform to the existing project

- Start with one active soundtrack per project. Add an import control and a waveform row aligned to the same ruler, zoom and playhead as the projection and Lighting rows. Display song name and duration. Use standard locally readable audio formats and reject unsupported, damaged, protected or over-limit media with a clear error.
- Inspect audio, copy it into the portable project and generate waveform peaks off the main thread. Bound decoding, peak storage and cache size. Replacing a song is one undoable edit and keeps existing cue and clip times. Flag material beyond the new song duration so the user can decide how to edit it.
- Propose format 11 with optional soundtrack and loop settings. Migrate existing projects with no soundtrack and preserve geometry, media, clips, lighting cues and preview placements. Reuse package save, media staging and recovery. A failed or cancelled import leaves the current song and file intact. Device selection, mute, playhead and transient waveform cache stay outside portable show data.

## 2. Make song playback the shared clock

- Reuse the current timeline controls and keyboard shortcuts. Add a loop range and show elapsed time and song duration. Use the audio playback position as the authority while a song is loaded. A project without a song continues on the existing elapsed-time transport.
- Play starts from the current position. Pause holds that position. Stop returns to zero and stops fixture output. Restart returns to zero and preserves whether playback was running. At the end, hold the playhead at song duration, stop audio and darken simulated fixtures. Starting again from the end begins at zero.
- A scrub pauses playback. A seek waits for audio to reach the requested position, updates all outputs from that position, and ignores stale completions after rapid scrubs. Loop an explicit start-inclusive, end-exclusive range. At wrap, reconstruct state at the loop start. Use the same discontinuity handling for restart and seek.
- Start with normal-speed song playback. Treat pitch-preserving variable speed as a separate validation step. Keep existing speed controls available in projects without a soundtrack. On an underrun or lost output device, hold the show position, show the reason and let the operator resume deliberately.

## 3. Rehearse with Mac audio, projection and simulated fixtures

- Start with the Mac's default stereo output. Add one song volume and mute control, an audio-only rehearsal option and a clear route status. Mute embedded video audio when a soundtrack is active, including when the song itself is muted. Preserve existing embedded-video behavior in projects without a soundtrack. Plan selectable audio devices and channel routing as a separate slice, with synthetic loss and fallback checks. Verify external audio hardware when available.
- Sample the shared song position for effect rendering, video frame requests and fixture evaluation. Keep the existing Test Window and fixture preview. After a seek, avoid showing stale decoded frames. Keep audio and fixture evaluation running if the editor is minimized.
- Keep fixture movement lead separate from projection compensation. Apply a saved projector offset once on the projector visual path, with explicit seek and loop boundaries. Test this with a synthetic clock and offset. Test Mode follows the uncompensated timeline. Optical calibration remains a later hardware check.

## 4. Verify and deliver the software rehearsal

- Use a generated reference song with timed clicks and a numbered video or deterministic effect. Align fixture cues with known click times. Test forward and backward seeks, rapid scrubbing, pause/resume, stop, end, repeated loops, simulated audio-route loss and save/reopen. Verify missing media and replacement failures preserve the existing project.
- Compare requested projection frames and simulated fixture changes against the song clock through a full reference track and repeated loops. Record offset, variation and drift separately. At a controlled 60 fps sample cadence, aim for the same sample or one sample of difference for evaluated software outputs. Record measured limits separately from any acoustic or optical timing.
- Keep checks focused during development. Verify the final build with pinned Xcode 27.0 beta 5 (27A5237l). For the user rehearsal, play the saved project on the Mac, scrub to a known click and loop a section in Test Mode while watching the fixture preview. Track user visual/listening acceptance separately from automated checks.

Resume v2.03 adapter transmission and v2.04 Arduino firmware/serial work when the devices are available, then verify both against the shared song clock.
