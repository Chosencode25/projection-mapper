# v2.11 Show Mode status

The November 22 implementation follows the five-part Show Mode plan in `V2_IMPLEMENTATION_PLAN.md`. Build 36 adds the operator and recovery code on `codex/v2.11-show-mode`. The package format stays at 16.

- The Show workspace pauses a running editor preview, locks editing, and requires local **Prepare & Arm** for playback and GO. The phone and keyboard use the same gate. Opening a project returns to Edit with the show disarmed.
- Preparation checks the existing geometry, layers, clips, asset and package constraints, selected audio and projection routes, and simulated controller failures. Critical blockers prevent arming. Preparation samples up to 12 distinct videos, prioritizing current clips, and uses the existing lookahead engine to warm up to four nearby clips. Test Window can be rehearsed in the main Show preview with the external window closed.
- Operator controls include Play, Pause, Stop, manual cues, queue, separate blackouts, audio mute, live brightness and fade duration, and object identification. Run state and operator settings do not change project data.
- The show checks output, audio routes, fixture failures and staged video availability while armed. An interruption holds playback, disarms the show and blacks out projection and fixtures. The operator resolves the fault, prepares, restores outputs and resumes. Sleep is treated as an interruption. Leaving a running show requires a deliberate pause or stop.
- The bounded Show Log keeps 40 events and reports playback preparation, interruption, buffering, late frames and detected renderer issues. The app retains its existing 256 MiB frame cache and lookahead limits. Video sampling verifies representative decode, while sustained performance and hardware acceptance require rehearsal.

See [the rehearsal guide](SHOW_MODE_GUIDE.md). The user requested installation and a GitHub source backup on the Show Mode feature branch. The installed app passed strict signature and file comparison checks. Build 35 is preserved. User acceptance remains pending.

## Automated verification

Xcode 27.0 beta 5 (27A5237l) ran the full Release regression suite with the two established visible-window exclusions. It reported 381 tests across 40 suites and no failures. Four optional performance checks were skipped. The Show tests cover arming and phone command gating, simulated controller faults, disarm and rearm without autoplay, bounded event history, identification and live gain without saved edits, video decode and lost staged media, and the timeline endpoint. The first run revealed that cached URL resource metadata masked file removal. The final run uses fresh filesystem attributes and detects the fault.

See `builds/show-mode/Release-final.log` and `Release-final.xcresult`. The ad-hoc signed app and archive contain arm64 and x86_64 and match the Release product. User rehearsal, live device failures, physical timing and Intel runtime acceptance remain pending.
