# v2.14 Phone Timeline and Preview

November 22, 2026. The requested phone workflow changes extend the existing Mac-hosted local browser and role system. v2.14 includes the v2.13 Project Home, playlist and schedule changes. Portable project format stays at 16.

- View paged timeline tracks and a bounded time range with stable owner, clip and cue IDs. Move, trim and adjust video source range through the existing Mac timeline validation. Timing edits update the desktop selection. Local simultaneous edits are rejected through the existing revision check.
- The browser keeps drags temporary until pointer release. It discards cancellations and guards against changed projects, locked workspaces and stale revisions. Numeric controls provide coarse or precise editing without gestures.
- A Mac Metal render pass generates one JPEG at a time with a longest edge of 480 pixels, a one-second minimum capture interval and a bounded response. Browser requests occur only while viewing. When the Mac window is hidden, preview briefly extends demand for the existing video decoder. Source media does not travel to the phone. The displayed age indicates snapshot delay.
- Pairing still requires approval. The primary phone can edit if granted Editor permission and the Mac is in Edit. Up to four separately approved viewer-only phones can read the timeline and share the preview. Viewer invitations keep the primary permission and session. The Mac may disable preview or revoke all phones.
- See [phone rehearsal](PHONE_TIMELINE_GUIDE.md) for the user acceptance checks.

## Automated verification

Xcode 27.0 beta 5 (27A5237l) ran the final Release suite and reported 390 tests in 42 suites with zero failures. Four optional performance cases skipped. The two established visible-window cases were excluded. The new checks exercise phone clip edits with connected faces, stale or removed clips, overlapping edits, save/reopen data, cue selection and undo, video source trims and bounds, JPEG size and stale-frame rejection. The local HTTP check approved two concurrent read-only viewers, denied their write commands, checked the preview permission, and verified revocation. The browser script passed syntax and synthetic gesture checks. Those checks exercised event handlers with stubbed browser controls. iPhone Safari, Android Chrome, foreground/network behavior on physical devices, and physical synchronization remain user rehearsal items.

Evidence is in `builds/phone-timeline/Release-final.log` and `Release-final.xcresult`. The local universal app and extracted archive matched all 11 files and passed strict signature verification.
