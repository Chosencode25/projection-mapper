# Projection Mapper — v1.02 Specific Plan

Status: implemented and locally verified October 5, 2026; physical external-display acceptance pending. See [V1.02_VERIFICATION.md](V1.02_VERIFICATION.md). A preview may be published from the feature branch while main remains v1.01; the final v1.02 tag/merge requires the recorded hardware checks.

## 1. Goal

Add reliable output selection to the existing editor. The user can choose **Test Window** or an independently usable connected display, inspect its current properties, and have the app remember that preference.

v1.02 selects the destination only. v1.03 creates the separate test/projector window, and v1.04 adds rendering. Selecting a projector in this milestone does not put anything on it.

Use Xcode **27.0 beta 5 (27A5237l)**, Swift 6 language mode, and the existing macOS 15.0 deployment target. Keep the interface entirely in SwiftUI and programmatic AppKit.

## 2. User-facing changes

### Toolbar

Add one compact **Output** picker near the inspector toggle. Test Window is always the first choice. Connected displays follow, using their system-provided names. Long names truncate visually but remain available through a tooltip and accessibility label.

The menu includes the display containing the editor as an unavailable choice labeled **Editor display**. Mirrored or otherwise unusable displays appear unavailable with a reason. A built-in display is identified as such, but eligibility depends on independent usability and editor location, not its array position or whether it is built-in.

Changing the picker updates the inspector, status bar, and placeholder canvas from one shared selection state. It does not open another window or move the editor.

### Inspector

Replace the current “Output: Not configured” row with an **Output Target** section containing:

- The same selection control, bound to the same state as the toolbar.
- Selected target name.
- Render size in pixels, when available.
- Desktop size in points and scale information for real displays.
- Reported refresh rate, when available.
- A short selection or connection message.
- A **Refresh Displays** action to repeat discovery manually.

Use “Selected” for a real display, not “Live,” “Projecting,” or “Output On.” Add a short note: “Output window arrives in v1.03.”

### Canvas and status bar

Keep the empty preview. Fit its outline to the selected target’s aspect ratio when known, without stretching its contents or creating a renderer. Test Window uses 16:9. If dimensions are unavailable, use 16:9 and say the size is not reported.

The status bar shows “Test Window selected” or “[Display name] selected.” Connection problems use inline status text instead of blocking alerts. Preserve the existing project-name and unsaved-change indicators.

## 3. Test Window specification

Test Window is a built-in destination choice, available even with no external display.

- Default target size: **1280 × 720**.
- Aspect ratio: **16:9**.
- Refresh-rate field: **Not applicable** at this stage.
- Size is descriptive configuration, not an actual allocated render buffer.
- Configurable simulated resolutions and the real resizable output window remain in v1.03.

The interface must make clear that choosing Test Window in v1.02 does not yet open it.

## 4. Selection and recovery rules

| Event | Required behavior |
|---|---|
| First launch | Select Test Window, including when an external display is already connected. |
| Later launch, saved Test Window preference | Select Test Window. |
| Later launch, saved real display uniquely matched and eligible | Restore that display as the selected destination. |
| Saved display missing, ambiguous, or ineligible | Select Test Window; show why the saved target could not be restored. |
| User selects an eligible display | Select it and save the explicit preference. |
| User explicitly selects Test Window | Save Test Window as the preference and clear any recovery notice. |
| A new display connects | Update available choices; preserve the current selection. |
| Selected display disconnects | Immediately fall back to Test Window once discovery confirms removal; retain the previous explicit preference and show the disconnected display name. |
| That display reconnects during the same run | Make it available again; keep Test Window selected until the user chooses the display. |
| Resolution, scale, orientation, or refresh information changes | Update metadata and aspect ratio without changing a still-valid selection. |
| Selected display becomes mirrored or contains the editor | Fall back to Test Window and explain the changed condition. |
| An unrelated display disappears | Preserve the current valid selection. |
| New Project | Reset project data while preserving output selection and app preferences. |
| Sleep/wake or application reactivation | Refresh discovery and revalidate selection. |

Startup preference restoration happens after the editor’s screen is known. Future output activation must remain a separate action; remembering a destination does not mean automatically starting projection.

## 5. Display discovery

Create one discovery service owned by the application coordinator, rather than a separate observer for each view.

- Read a fresh `NSScreen.screens` snapshot when discovering drawable desktop screens.
- Use `localizedName` for names where available.
- Use Core Graphics online-display information to detect mirror members and connected displays that do not have independent NSScreen entries.
- Map screen descriptions to current Core Graphics display identifiers.
- Read current display-mode metadata and built-in/mirroring information.
- Observe `NSApplication.didChangeScreenParametersNotification` and the editor window’s screen-change events.
- Refresh on application reactivation and through Refresh Displays.
- Keep state updates on the main actor and coalesce bursts of configuration notifications.
- Register observers once and clean them up with their owner.

Do not assume `NSScreen.main` means the built-in screen, or that the first screen is the laptop display. Keep physical projector-versus-monitor classification out of the UI: macOS may report either as an ordinary display.

Show a mirroring explanation such as “Use an extended display in System Settings → Displays.” Do not change system mirroring, resolution, refresh rate, or display arrangement.

If discovery temporarily fails or returns incomplete data, choose Test Window safely, retain the explicit saved preference, show an inline explanation, and allow a retry. Do not erase the preference because of one failed scan.

## 6. Metadata and identity

Each display descriptor contains:

- A runtime display identifier for resolving the current screen.
- An optional Core Graphics display UUID for preference restoration.
- Display name and built-in/external classification.
- Current desktop frame in points.
- Current render dimensions in pixels, with current orientation handled correctly.
- Backing scale information.
- Optional reported refresh rate.
- Mirroring status and eligibility reason.

Persist a uniquely usable UUID, not an array index, display name, or runtime numeric identifier alone. If identity is unavailable or ambiguous, require manual selection after restarting rather than choosing by name. Display numbering can distinguish duplicate menu labels but is not persistent identity.

Keep desktop points, rendering pixels, and physical panel resolution distinct. Label the pixel measurement **Render size** rather than claiming it is the panel’s native resolution. Prefer current mode pixel dimensions; if falling back to backing-coordinate conversion, label the result as an estimate.

Display a finite positive reported rate such as “59.94 Hz.” If the system returns zero or unavailable data, show **Not reported**, not “0 Hz” or an invented 60 Hz. A display’s maximum capability is not its current reported rate.

Invalid or missing dimensions must not produce division-by-zero, a collapsed canvas, or an unselectable Test Window.

## 7. State and persistence

Keep output configuration in application/session state, separate from MappingProject.

- `OutputDestination`: Test Window or a selected real display identity.
- `DisplayDescriptor`: plain display information, suitable for testing without hardware.
- `OutputSelectionState`: inventory, active selection, and inline recovery message.
- `OutputPreferences`: explicit last-choice storage in UserDefaults.

Separate active selection from saved preference so temporary fallback does not overwrite the user’s last explicit choice.

Output changes and display notifications do not modify project timestamps or `hasUserChanges`, and do not trigger the project discard alert. Project-level output configuration remains future work for v1.14.

Views consume descriptors, not retained NSScreen objects. Re-resolve a live screen when v1.03 actually creates an output window.

## 10. Verification

### Automated state tests

Cover initial Test Window selection; saved preference restoration; missing/ambiguous identity; explicit selection persistence; disconnect fallback without losing preference; reconnect without automatic switching; unrelated display removal; metadata changes with stable identity; mirrored/editor-display rejection; invalid dimensions; unknown refresh formatting; and New Project leaving output preferences intact.

Use an isolated UserDefaults suite so tests cannot change real app preferences. Fixtures must cover duplicate names, changed array order/runtime IDs, HiDPI data, and rotated dimensions. Tests must assert user-visible behavior, not just repeat individual implementation lines.

Run the existing five v1.01 state tests as regressions.

### Manual acceptance checks

- Launch without an external display and confirm Test Window remains usable.
- Connect a real external monitor or projector in extended mode; select it and compare reported information with system settings.
- Unplug the selected display; verify fallback, retained project name, and inline explanation.
- Reconnect it; verify it returns to the menu without taking over selection.
- Restart with a saved connected display, and again with it disconnected.
- Test mirroring and moving the editor between displays.
- Change display scaling, resolution, or orientation where supported.
- Verify duplicate names or multiple displays when hardware is available; otherwise record fixture-only coverage.
- Inspect minimum and larger editor layouts, long names, keyboard selection, and accessibility labels.
- Confirm New Project resets only project data and existing Cancel/Discard behavior remains intact.
- Confirm selection never opens an output window or changes system display settings.

Actual connected-display detection requires a recorded physical monitor/projector check. If hardware is unavailable, record it as unverified rather than claiming it passed.

## 11. Done criteria

v1.02 is complete when discovery and both pickers share consistent state, default/fallback rules work, preferences survive relaunch, metadata is accurate or honestly unavailable, hot plugging and mirroring do not crash or select the wrong target, v1.01 regressions pass, and the required hardware check is recorded.

The app must build and run with **Xcode 27.0 beta 5 (27A5237l)**. Deliver source, a verified local build, updated progress/changelog/verification notes, and a private GitHub v1.02 prerelease tied to its tested commit. No v1.02 tag or release is created for the planning document alone.
