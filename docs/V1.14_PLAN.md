Planned October 9, 2026 at the user's request; implementation authorized by the subsequent “do that now” instruction. The seven stages are implemented, automatically verified and delivered locally. See [verification](V1.14_VERIFICATION.md); user visual/listening acceptance remains pending. The complete milestone is organized into seven implementation steps; these are work stages, not separate version numbers.

Read PROJECT_DEVELOPMENT.md and V1_REMAINING_PLAN.md before implementation. Exact Xcode 27.0 beta 5 (27A5237l) reverified during planning. Installed SDK headers confirm native seek-completion, host-time rate scheduling and macOS audio output-device APIs; runtime behavior still requires implementation tests.

## Starting point and completion contract

The installed 1.13/build 10 app already has images/reference photos, object/standalone-face ownership, geometry/input maps/joins, masks/calibration, portable save/recovery and a working bottom timeline. Format 8 stores EffectClip IDs, source-owner IDs, start/duration and captured SourceLook content. Preview/Test Output share AnimationTransport and render-time evaluation. Current baseline is 245 passing correctness tests per Debug/Release configuration; routine user visuals are pending.

1.14 extends that implementation. Finished means a user can import a video, place it in the existing object row, select a source range, trim/move/duplicate it, play or scrub alongside effects/images, use connected faces, deliberately enable audio, and Save/Open a portable project without losing content or creating duplicate streams. A tested Release app is delivered to app/; the previous app and historical archives remain preserved.

Music/song imports, waveforms/beat markers, overlapping layers/crossfades, export, physical projector output and timeline undo are outside this milestone. Undo/redo and final readiness remain v1.15. V2 reuses this transport/timeline foundation.

## 1 — Video data and safe import

- Add VideoAsset metadata with stable UUID, bounded safe package filename, original display name, inspected duration, pixel size/display orientation, audio presence and supported codec/color information. Add VideoContent to SurfaceSource/SourceLook and a video branch to SurfaceContent without changing existing source/target identities.
- Use a VideoImportService to inspect local regular files asynchronously through AVFoundation. First supported fixtures: SDR H.264/HEVC video in MP4/MOV containers. Container extension alone never proves support: load track properties and decode a representative frame. Reject unusable, malformed, missing-track or unsupported-color media clearly; test supported codecs rather than promising every AVFoundation format.
- Use native import plus file drop with the existing independent/shared-owner/detach decision flow. Capture the selected owner/project generation before async work; cancellation, deletion, New/Open or intervening replacement invalidates stale completions. Failed import leaves current content/mapping intact.
- Copy original media bytes into an application-managed staged asset location, off the main actor, using progress/cancellation and bounded chunked I/O. Avoid storing whole videos in Data. Suggested initial validation limits: 64 video assets, 2 GiB per file and 8 GiB total project video bytes; publish final supported limits after fixture/profiling checks, without silently weakening them. Budget poster/frame caches independently.
- Generate a bounded poster and expose filename, source duration, dimensions and loading/problem status. A successful import starts paused/muted; selecting video content does not start audio.

Acceptance: valid MP4/MOV imports, silent/audio-bearing and rotated fixtures, invalid/unsupported media, symlink/path bounds, cancellation and stale completion tests. Source geometry and masks are unchanged.

## 2 — Extend existing clips with source ranges

- Keep the current owner rows, ruler, playhead, zoom, snap/follow and selection controls. Add video thumbnail/name/duration to a block and a selected-video strip with source In/Out, source playback rate, loop and placement controls.
- Store a source range [inPoint, outPoint), positive source rate and explicit loop policy with the captured video content. Initially use the existing speed choices as candidate source rates; enable only runtime-verified media rates. Existing effect/image payloads retain their current semantics.
- Evaluate requested source time from the single project transport: inPoint + (timelineTime - clip.start) × sourceRate. Looping wraps within the chosen source range; global transport speed changes how quickly timelineTime advances. Non-loop clips cannot extend beyond their available source range. Clip intervals remain start-inclusive/end-exclusive.
- Moving a video block changes its timeline start, retaining its source range. Leading trim changes both start and source in-point; trailing trim changes timeline end/source out-point. Example: a block at timeline 10–20 seconds using source 3–13 at 1×, trimmed two seconds on the left, becomes timeline 12–20 using source 5–13. Reject invalid ranges and overlaps atomically, with a visible reason.
- Add/re-capture uses the selected video's inspected range; an imported video shorter than the current 0.1-second clip minimum gets a clear unsupported-duration message. Respect the existing 3600-second timeline and 2000-clip limits. Duplicate retains the selected footage with a fresh clip ID.
- Sequenced-row gaps stay dark. Empty rows keep live content: a non-looping live video holds its final frame when exhausted; looping repeats its selected range. At paused start/open, show the first requested frame. Deleting the last clip restores live content. Define Capture Current video-range replacement visibly and validate it before committing.

Acceptance: pure time/range tests for move versus leading/trailing trim, rate and global speed, loop boundaries, minimum length, source bounds, duplicate/recapture and existing effect/image behavior. No mixed-content sequence changes its mapping.

## 3 — Shared decode, transport and Metal frames

- Add a VideoPlaybackCoordinator outside view ownership. One active decode/playback state belongs to each content owner, shared by every linked face and by editor/Test Output. Two independent objects can use the same asset at different source times with independent playback states.
- Bridge AVFoundation frames through Core Video/Metal resources with explicit pixel-buffer/texture lifetime. Publish immutable frame snapshots keyed by owner, active clip/generation and requested time. Both render views consume the same selected frame; they do not own separate players or advance time by frame count.
- Reconcile running playback against AnimationTransport host-time anchors. Pause/seek/restart/rate changes are explicit discontinuities: cancel obsolete requests, await/validate seek completion and publish only a frame matching the current request. Never reuse the outgoing video's frame as the incoming clip's frame. A not-ready requested video is dark with editor status; the previous clip is not displayed accidentally.
- Preload adjacent video clips within a bounded window. Reusing an asset at two different in-points must still handle the clip boundary as a discontinuity. Cap app-owned decoded-frame caches (initial target 256 MiB) separately from AVFoundation's internal allocations; measure actual total process memory rather than claiming the cache limit bounds every decoder allocation.
- Support existing transport Play/Pause, Stop/return-to-start, restart, one-second steps, ruler scrubbing and speed controls. Timeline-owned sources use global transport; live sources retain explicit owner pause/restart behavior. Video does not introduce an independent master clock or per-face clock.

Acceptance: frame-number fixtures at exact requests, paused seeks, backwards seeks, skipped presentation frames, rapid seeks/rate changes, adjacent video/effect/image blocks, same-asset discontinuities and equal preview/output frames. Record observed frame selection/timing limits; do not promise universal frame accuracy.

## 4 — Mapping, resource lifecycle and editor integration

- Extend the existing image texture sampling path for video while retaining Fit/Fill/Stretch, crop/flip, input maps, perspective, masks and opacity/brightness. Normalize orientation and supported SDR color consistently; unsupported HDR/alpha cases are reported explicitly until verified.
- Continuous linked faces sample one frame across the shared canvas; Repeat samples the entire same frame on every face. Apply existing geometry/appearance/mask rules without baking timeline edits into layout.
- Add replace/remove/relink actions. Asset relink keeps asset identity but must re-inspect duration/format and validate every live/clip source range; an incompatible shorter replacement requires explicit range correction, not silent truncation.
- Carry the established object lifecycle through video: member duplicates share their object; object/standalone duplication and detach get independent playback ownership with copied declarative ranges. Group/attach adopts the destination owner's content/sequence; deletion prunes targets and releases resources only after live content, clips and looks no longer reference them.
- Suspend unnecessary visual decoding when no eligible view can use it; hidden/zero-contribution owners and closed/minimized views should not waste visual work. Explicit audio policy can keep audible playback running. Reopening output, returning from calibration or restoring blackout requests the current transport frame, not the suspended frame.

Acceptance: offscreen GPU placement/orientation/crop/mask/compositing checks, connected edge samples, Continuous/Repeat, duplicate/detach/delete/replace stress, calibration/blackout restoration and observer/cache teardown.

## 5 — Embedded audio with clear ownership

- Video audio is muted by default. Add explicit owner/clip mute, project master audio volume and selectable macOS output device; audio settings are distinct from visual brightness/fade/blackout.
- One owner produces one audio stream even with several faces and both render views. Multiple explicitly unmuted owners may mix; opening a second output view does not add another stream. Silent videos expose a clear no-audio state.
- Synchronize audio to the same clip/source range and transport discontinuities as frames. Pause and Stop silence audio; scrubbing is silent and resumes only on Play. Gaps or transitions to image/effect clips stop outgoing video audio. Loop/rate changes reset source timing coherently.
- Verify supported audio rates/pitch handling using actual fixture capabilities. For an unsupported audio rate, explicitly report/silence that stream rather than playing at the wrong speed; do not silently change global transport speed. Record supported combinations.
- Persist intended audio preferences but reopen paused with a runtime mute safety override. If a selected device disappears, mute/report it; do not automatically route an audible show to an unrelated device. Restoring output requires a deliberate user action. Blackout alone leaves deliberately enabled audio unchanged.

Acceptance: fake audio-sink tests for one stream/owner and command ordering; actual audio fixture timing/routing checks; pause/stop/scrub/gap/loop/rate and device-loss tests. User listening checks are recorded separately from automated command verification.

## 6 — Portable projects and recovery

- Evolve format 8 to the next version (planned format 9) for video assets/ranges/audio settings. Decode/migrate formats 1–8, including existing timeline clips, images, looks, photo and masks. Do not renumber existing IDs or alter generator phase/timing during migration.
- Collect media referenced by live sources, timeline-only clips and saved looks. Save/Save As/recovery copy from managed assets using staged replacement, progress/cancellation, space checks and safe filenames. An interrupted copy retains the last good package and current unsaved session.
- Open validates metadata, references and actual media before replacing runtime resources. Missing/unreadable video preserves mapping, metadata and clip references with actionable relink state. An incomplete project cannot be declared successfully saved as a fully portable copy. Opening never starts playback or audible output.
- Retain source ranges on relink and reject conflicting identities. Verify orphan collection after deleting clips/looks and final-owner removal. Preserve a path to v1.15 undo asset retention rather than deleting referenced media during an in-progress transaction.

Acceptance: moved/copy-open packages, timeline-only assets, Save As, untitled recovery, failed/cancelled writes, missing/shorter relinks, malformed/newer files and complete format 8 fixtures with existing image/effect timelines.
