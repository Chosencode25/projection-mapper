# v1.04.4 — Rendering Lifecycle

Status: planned, not implemented or verified. Approved five-slice breakdown: October 5, 2026. Depends on v1.04.3. See [v1.04 master plan](V1.04_PLAN.md).

## Implementation

- Handle drawable-size changes and temporarily unavailable drawables safely.
- Pause or reduce unnecessary rendering when the corresponding view is hidden, minimized, or closed; restore drawing when visible.
- Coordinate render ownership and GPU resource cleanup with output close/reopen and app shutdown.
- Preserve independent editor/output behavior and prevent accumulating render loops or resources.

## Acceptance

Repeated window operations behave correctly without accumulating resources.

Exercise repeated open/close, minimize/restore, resize, resolution changes, editor navigation, and quit; inspect resource/loop ownership.

## Delivery and boundaries

Use Xcode 27.0 beta 5 (27A5237l), SwiftUI/programmatic AppKit, and Metal. Run relevant focused checks and regressions during this slice; update progress/verification notes and the local runnable build. Commit and push tested source through a feature branch into main. No automatic bundle bump, tag, archive, or release.

Projector implementation and physical reconnect checks remain deferred. Actual mapping surfaces begin in v1.05; corner dragging, perspective warp, images, and video belong to later milestones.
