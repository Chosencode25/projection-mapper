# v2.07 — Phone Browser Editor and Remote

Planning draft, November 11, 2026. Start from the verified v2.06 Edit and Show workspaces after that source is recorded in Git. Use the Mac, Test Mode and simulated fixtures for development and rehearsal.

**First walkthrough.** Start Phone Remote on the Mac, scan its QR code from a phone on the same Wi-Fi, approve the phone, and use it to run the existing rehearsal. Then switch the Mac to Edit, identify a surface from across the room, adjust a corner and mask, change an effect, undo and redo, and save the project on the Mac.

## 1. Prove browser pairing on the local network

- Build the Mac settings panel and a minimal phone page first. The service starts off and listens only after the user chooses a local interface and enables it. Show its current address, connection status, Stop Remote and Revoke Phone controls. Generate a QR code and provide the same address and pairing code in text.
- Prototype browser-trusted HTTPS on a local hostname before enabling control. Evaluate an explicitly configured hostname with local DNS and a trusted certificate. DNS-based certificate issuance is a candidate for provisioning without exposing the server publicly. Check certificate renewal, hostname resolution and offline rehearsal after setup. Record the prerequisites before choosing a default setup. The QR code identifies the endpoint and invitation. The browser must independently trust the endpoint.
- Use a short-lived, single-use invitation followed by Mac approval. Give the approved phone a revocable session with explicit Viewer, Operator or Editor permissions. Keep one editing controller at a time. Invalidate sessions when the service is stopped, the network interface changes or the Mac restarts.
- Verify the listener and browser trust flow on iPhone Safari and Android Chrome before claiming phone compatibility. In parallel, develop and test the commands on the Mac with a loopback client.

References for the connection prototype. [W3C secure contexts](https://www.w3.org/TR/secure-contexts/), [Apple local network privacy](https://developer.apple.com/documentation/Technotes/tn3179-understanding-local-network-privacy), [Let’s Encrypt DNS-01](https://letsencrypt.org/docs/challenge-types/).

## 2. Build the phone remote around Show

- Display the project, workspace, current song and playhead, next timed cue and countdown, and whether projection and fixtures are available, simulated, or blacked out. Reuse the Mac's loop-aware cue calculation.
- Add Play, Pause, Stop, Seek, manual GO, projection blackout and restore, fixture blackout and restore, and deliberate audio enable or mute where the Mac exposes those actions. Show the Mac's acknowledgement and resulting state after each command.
- Apply the same lock as the desktop. In Show, an Operator can run the rehearsal and an Editor can see the edit lock. Returning to Edit during playback requires the existing Mac **Pause and Edit** action. Project switching, physical arming and device or patch configuration stay on the Mac.

## 3. Build the phone editor

- List surfaces and linked objects. Identify a selection on the output, then finish identification. Provide a mapping diagram with corner drag handles, magnification and nudge buttons. Respect geometry locks, stable target IDs, normalized coordinates and linked-object behavior.
- Add boundary and hole editing for face masks using the Mac's validation. Keep one undo step per completed drag or mask edit. Preview drag changes at a bounded rate and cancel an unfinished gesture on disconnect.
- Add effect controls, colors and palettes, and brightness. Use existing Mac edit and history paths for Undo, Redo and Save. For a project with no save location, request the location on the Mac and show the pending result on the phone. The phone starts with a mapping diagram. The live rendered preview and mobile timeline are scheduled for v2.14.

## 4. Verify concurrency, recovery and the rehearsal

- Tag edits with a project ID, state revision and unique command or gesture ID. Publish committed Mac edits back to the phone. Reject a stale edit with the current state, deduplicate retries, validate targets and values, and limit request size and rate. Disconnect and reconnect should load current state. Playback continues according to the Mac's current state.
- Test pairing expiry and revocation, wrong-origin requests, role enforcement, Show locks, simultaneous Mac and phone edits, invalid geometry, duplicate requests, interrupted gestures, and save/reopen. Run focused checks per slice and the full milestone checks using Xcode 27.0 beta 5 (27A5237l).
- Rehearse the 3–7 second loop from the phone using Test Output and simulated fixtures. Test phone portrait and landscape, then adjust and save one mapped surface and reopen it on the Mac. Record browser and network results, acknowledgement latency and playback during dragging. Physical DMX, Arduino and projector checks follow when equipment is available.
