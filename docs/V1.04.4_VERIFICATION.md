# v1.04.4 — Rendering Lifecycle Verification

Date: October 5, 2026. Status: implementation complete; automated verification passed. The two deferred onscreen tests subsequently passed at the user’s request; broader manual acceptance remains pending.

## Implementation

MetalSceneView keeps MTKView paused and uses invalidation for this static scene. Drawing is enabled only when attached to a visible, non-minimized, non-occluded window, with a non-hidden, finite, positive-sized surface. Window occlusion, minimize/restore, backing, attachment, and hide/unhide callbacks update eligibility and invalidate eligible surfaces. MetalRenderer checks that gate before acquiring a render pass/drawable, and safely skips unavailable drawables.

Closing output stops drawing, releases cached drawables, clears content/delegate ownership, and permits a fresh renderer on reopen. The editor renderer is independent. Editor close and application termination drop the editor hosting content and close output. GPU work already submitted retains its own resources until completion; no new timer, display link, or render loop was introduced.

Window presentation is injectable into TestOutputCoordinator and EditorSession. Automated window tests use a no-op presenter; hosted preview layout does not order a window onto the desktop. Production defaults retain normal presentation.
