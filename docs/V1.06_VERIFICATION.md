## Implemented behavior

- Selected Surface 1 has four editor-only handles and a closed outline above the fitted Metal preview. Active corner is purple; other handles are white. Controls include a 12-point outside inset so canvas-edge handles remain reachable. These controls are never added to Test Output.
- Clicking a handle selects it and gives the native overlay keyboard focus. Dragging preserves the initial grab offset, converts flipped editor points through the exact fitted preview rectangle, clamps finite normalized coordinates to 0…1, and updates the project and existing output scene. SwiftUI refreshes the existing preview scene too.
- Normal arrow keys move the active corner by 0.001 normalized units (0.1% of the corresponding axis); Shift uses 0.01 (1%). Down increases y, up decreases it. Native key-repeat events use the same path. Command/Control/Option arrows are not treated as nudges. No global event monitor intercepts text-field keys.
- Escape clears active corner selection. Background clicks clear the corner; surface deselection hides the outline/handles and clears the active corner. Reselecting restores handles without changing geometry. Reset creates a new default surface and clears the active corner.
- Actual geometry changes update modifiedAt and activate discard protection. Corner selection, invalid/stale-ID requests, and clamped no-op moves do not modify the project. Preset changes, panel state and output close/reopen remain independent of geometry.
- Inspector identifies the active corner, gives keyboard guidance and shows all coordinates to three decimal places. The existing solid two-triangle fill follows the edited geometry; perspective-correct texture mapping remains v1.07.
