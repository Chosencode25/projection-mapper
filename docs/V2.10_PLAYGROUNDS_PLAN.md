# v2.10 first part — Playgrounds

November 17, 2026. User authorized the saved Playgrounds workflow and build order. Implemented locally on `codex/v2.10-playgrounds`, carrying the existing build 31 changes forward without committing or replacing their history. Active source remains `builds/worktrees/v2.09/app/ProjectionMapper/`. This directory name is historical.

## Scope and sequence

1. One allowlisted setup extraction shared by Save Playground, New Show from This Playground, library-based creation, From Project File, and library updates.
2. Save Playground and direct new-show creation, preserving the original show and the existing save-before-switch handling.
3. Local library chooser, independent named autosaved drafts, optional song selection using the existing soundtrack importer, and extraction from supported project packages.
4. Rename/note, duplicate, deliberately confirmed setup update, import and export.
5. Automated extraction/package/independence/failure checks and full regression; user visual/listening rehearsal remains a separate acceptance step.

## Saved-field contract

| Project fields | Treatment |
|---|---|
| Project ID, name, creation/modification dates | New identity, supplied name and fresh dates. Internal target IDs remain coherent within each independent document. |
| Surfaces and objects | Keep names/tags/order, membership, corners, input maps, links, mode, locks, visibility, appearance/overrides and masks. Reset every source, including dormant sources on connected faces. |
| Layers and face regions | Keep owner/face IDs, names, visibility, blend, opacity, position/size/rotation, region shape and outline. Clear source assignments, source kind, projected words, countdown/marker targets and mouth keys. |
| Region shape presets | Keep reusable geometry. |
| Reference photo and image assets | Keep photo placement/settings and only the referenced photo asset/bytes. |
| Video assets/audio routing, soundtrack | Empty/default. New song selection is a subsequent independent import into the new show. |
| Timeline clips, markers, choreography | Empty. |
| Generator presets, palettes and projection looks | Empty. |
| Fixture controllers and patched fixtures | Keep supported profiles/configuration, groups, addresses and placements represented by the existing model. |
| Lighting looks, cues and moving-head position keys | Empty. |
| Master output | Keep static brightness; reset fade timing to default. |
| Output preference/resolution | Retain as configuration hints; normal loading resolves device availability and leaves output closed. |
| Recovery metadata/runtime | No recovery provenance in a playground. New shows reset clock/history/selection, manual fixture state, calibration and audio overrides; the phone remote is stopped. |

Base targets start solid black. Empty overlay and region targets are transparent so they do not obscure newly programmed base content. Fixtures remain stopped/dark; transport starts paused at zero. Projection-only and lighting-only setups are valid.

## Packaging and switching

Playgrounds use `.projectionplayground` packages, with `playground.json` schema version 1, an embedded project `manifest.json` (format 14 initially; format 15 in build 34), and required reference-photo assets. The initial Playground slice needed no portable-show schema bump; later moving-head keys require format 15 in build 34. Decode/migrate supported projects through the existing project reader. Reject future playground schemas and snapshots containing programming.

Save/update/export stages and validates the complete package before the existing atomic replacement. The writer prunes inherited unrelated assets. New-show creation writes and validates a separate UUID-named draft before adopting it. Failures keep the original project open; failure during playground replacement preserves the last valid saved playground. Each existing show owns its own setup snapshot.

The initial build 32 used Edit. The local build 33 Lighting section additionally enables choosing Edit or Lighting for a new show. Broader v2.10 layout roles, programmed templates/palette packs and performance recording remain planned. This slice does not complete v2.10 and does not trigger Git delivery or release publication.
