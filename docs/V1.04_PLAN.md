# v1.04 — Metal Renderer

Status: v1.04.1–v1.04.2 implemented and locally verified; v1.04.3–v1.04.5 remain planned. The approved plan is five sequential slices, recorded October 5, 2026. v1.03.3 is the verified starting point.

## Outcome

Move from a blank Test Output window to a reliable Metal-rendered rectangle, then matching editor/output views using shared rendering code and scene data. Keep normalized scene geometry independent of window size and simulated resolution. Prepare the renderer for future projector use; projector-window implementation and physical disconnect/reconnect testing remain deferred.

## Development slices

| Slice | Scope | Completion checkpoint |
|---|---|---|
| [v1.04.1 — Metal Foundation](V1.04.1_PLAN.md) | Device, drawing view, fixed-color clear, initialization errors. | Output reliably draws through resize, close, and reopen. |
| [v1.04.2 — First Rectangle](V1.04.2_PLAN.md) | Shader pipeline, temporary rectangle, normalized geometry and sizing. | The rectangle keeps its intended position and proportions across presets and window sizes. |
| [v1.04.3 — Shared Editor Preview](V1.04.3_PLAN.md) | Shared renderer/scene data, matching preview and clean output. | Both views consistently show the same content. |
| [v1.04.4 — Rendering Lifecycle](V1.04.4_PLAN.md) | Drawable changes, visibility, pause/resume, resource cleanup. | Repeated window operations behave correctly without accumulating resources. |
| [v1.04.5 — Performance and Acceptance](V1.04.5_PLAN.md) | Frame pacing/GPU measurements, targeted tuning, final regressions. | We have a stable renderer and documented performance on the development Mac. |

Each slice has an independently verifiable result. Test throughout development; the final slice adds performance measurement and overall acceptance. The shared-preview work is separated from rectangle/coordinate work, and lifecycle work is separated from performance tuning.

## Requirements and existing behavior

- Exact toolchain: Xcode 27.0 beta 5 (27A5237l); verify it before code work and use per-command DEVELOPER_DIR. Keep macOS 15.0 minimum and the interface in SwiftUI/programmatic AppKit.
- Preserve HD, Full HD, 4:3, Portrait, and 4K presets, preference restoration, aspect-preserving output, and black margins.
- Preserve the single Test Output window, normal-frame persistence/recovery, closed startup, Show Output/Editor shortcuts, and project-independent output preferences.
- The renderer can have separate per-view resources while sharing scene definitions and rendering implementation. Editor interface elements must not appear in clean output.
- A temporary diagnostic rectangle is sufficient. v1.05 introduces the first actual mapping surface; v1.06 adds handles and v1.07 perspective warp. Media and animation remain later stages.
- Establish the performance target from measurements on the development Mac; do not claim unmeasured 4K rendering based solely on a simulated-resolution label.

## Saving and delivery

Keep source under app/, plans/progress/verification under docs/, project-owned media under assets/, and local outputs under builds/. Start each subsequent slice on a feature branch from tested main. Verify the work, update documentation and the runnable local app, then commit/push and advance main. Small slices do not automatically need bundle version bumps, tags, archives, or GitHub Releases. Preserve published milestone tags/assets and read-only source mirrors.
