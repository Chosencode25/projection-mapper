# v2.07 — Phone Remote and Editor

Open the current project on the Mac and choose **Phone Remote** from the top of either workspace. The service is off at launch.

1. In build 30, connect the Mac and phone to the same trusted home network. Click **Start Local Remote**. The app automatically chooses a private address, preferring Wi-Fi. If several addresses are listed, choose the one on the phone's network. **Refresh Networks** updates the list. The QR code uses the selected address on port 9443. Local HTTP is unencrypted and Safari may label the page Not Secure.
2. Scan the QR code from the phone. You can also open the displayed URL or enter its invitation on the pairing page. Choose **Viewer**, **Operator** or **Editor** on the Mac and click **Approve Phone**. One phone can be approved at a time. Use **New Invitation** to replace an expired code.
3. With Operator or Editor permissions, try the 3–7 second rehearsal loop. Check the playhead, next cue, projection and fixture blackout, GO, and readiness. The Mac continues to control playback if the phone disconnects.
4. With Editor permissions, switch the Mac to **Edit**. Choose a face on the phone. Identify it, drag a corner or use a nudge button, then check the mapping in Test Mode. The zoom slider magnifies the selected point. The mask view supports dragging existing vertices and applying a boundary and hole list. You can use the palette or set effect rate, scale and intensity. Undo, redo and save from the phone. For an unsaved project, finish the save dialog on the Mac.
5. Switch to **Show** and confirm that mapping changes are blocked while transport controls remain available. Revoke the phone from the Mac and confirm it needs a new invitation.

The default Local Remote setup is hosted entirely by the Mac. Its automated test covers HTTP pairing over an automatically selected private network address. Real Safari and Chrome pairing, touch interaction, and latency remain device checks. Test without internet service as a separate rehearsal.

For encrypted use, expand **Advanced HTTPS** and enter the DNS hostname, private address, identity file, and password. The phone must resolve that hostname and trust the certificate. This path retains its automated HTTPS loopback check.
