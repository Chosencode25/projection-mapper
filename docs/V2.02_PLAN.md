# v2.02 — Fixture Patching and Simulation

Planning draft, November 8, 2026. Start from tested v2.01 on a local `codex/` feature branch when implementation begins. See the [V2 implementation plan](V2_IMPLEMENTATION_PLAN.md) and [moving-head reference](NATIVE_DMX_FIXTURE_REFERENCE.md).

The rehearsal should let someone patch a moving head, switched plug and RGB strip, test them individually, capture two lighting looks, and cue those looks alongside projection in Test Mode. The monitor should show the intended state and simulated output for both controllers throughout the rehearsal.

## 1. Patch fixtures and save the layout

- Add a Fixtures workspace with a controller list and fixture assignments. Use stable IDs for controllers and fixtures, editable fixture names and groups. A DMX controller owns a 512-slot address space. An Arduino controller has a configured output count with one-based labels in the editor. Keep protocol support and assignment status visible.
- Offer CH 9 and CH 11 footprint choices for the documented moving head. Reserve the entire footprint and reject overlaps or addresses that spill beyond 512. A plug claims one relay output and an RGB strip claims three distinct outputs in red, green, blue order. Reject collisions within each controller and out-of-range relay outputs. Separate controllers can reuse address numbers.
- Apply a patch only after validating the whole proposed edit. Repatching preserves the fixture ID. Require explicit confirmation before deleting a fixture that is used in looks or cues. Remove dependent entries and any resulting empty looks or cues in one undoable edit. Keep type-specific state valid by treating a change of fixture type as removal and addition.
- Extend `MappingProject` and `ProjectCodec` with separate patch and cue data inside the existing package. Propose format 10, migrating formats 1–9 to empty fixture data while preserving existing IDs, geometry, media, clips and settings. Reuse `EditorSession` edit history, validation, dirty tracking and recovery. Keep port bindings, connection state, overrides and blackout outside the package.
- Check boundary addresses, CH 9 and CH 11 overlaps, duplicate RGB outputs, controller capacity changes, migration of the bundled demo and save/reopen with mixed media. Verify that an invalid edit leaves the last valid patch intact and that undo restores references.

## 2. Test fixtures and capture looks

- Show controls for pan, tilt, dimmer, fixed color and gobo on the moving head, on/off for the plug, and eight discrete RGB swatches including off. Use fixture-level values so the native transports can consume the same intended state in later milestones.
- Allow an explicit manual override per fixture and a way to clear it. Capture a reusable named look for selected fixtures as a complete state for each included fixture. A cue placed from a look gets a copy of those states so editing the reusable look does not change previously placed cues.
- Keep one visible fixture blackout control independent of projector blackout and audio mute. Blackout forces the head dimmer, plug and RGB outputs off while retaining the intended head position. The monitor shows the active override or blackout alongside the effective values.
- Check that capturing and editing looks is undoable and that temporary controls leave the document clean.

## 3. Add cues to the existing timeline

- Add one Lighting lane using the existing ruler, playhead, zoom and snap. Place a cue at the playhead, then select, move, duplicate or delete it. Include cue times in the visible timeline range. Use the current 0–3600 second edit range and reject two cues for the same fixture at the same time. Allow different fixtures to change together.
- Evaluate the latest cue at or before the shared elapsed time for each fixture. Hold that state until the next cue for that fixture and start dark before the first cue. Apply color, gobo, dimmer and relay changes at the cue time. A per-cue lead may send only the moving head's pan/tilt target early. Clamp the lead to the timeline start or the previous cue for that fixture, whichever comes later. A lead target is a position command. Physical travel time is measured in v2.03.
- Read the existing `AnimationTransport` in the session. Keep fixture evaluation independent of renderer draws and timeline visibility. Pause holds the evaluated state. Seek, restart and a simulated loop wrap rebuild state at the destination without replaying skipped cues. Verify loop behavior by feeding a wrap into the evaluator. Song loop controls belong to v2.05.
- Apply precedence in this order, from highest to lowest — fixture blackout, explicit fixture Stop, manual override, timeline cue, default dark. Provide Stop in the fixture workspace. It forces dark, clears overrides and holds fixture cues until explicit resume or a new playback start. Pause and seek alone do not release Stop. Opening or recovering a project starts fixture output dark and clears runtime overrides. Test exact cue and lead boundaries, both seek directions, wrap, restart, pause, Stop and resume.

## 4. Simulate and verify a rehearsal

- Add two simulation sinks behind the fixture evaluator, one for DMX assignments and one for Arduino relay assignments. Label the monitor **Simulation** and show intended state, effective state and the most recent simulated send or failure by controller. Report unconfigured or unsupported profiles explicitly. Bound update cadence and retain only a short send history. USB adapter packet encoding and Arduino firmware commands remain in their native milestones.
- Inject a failure into each simulated controller independently. Confirm that the other controller and projection keep running and that the monitor distinguishes failed output from intended values. Check that closing Test Mode or hiding the timeline does not stop fixture evaluation while the project is playing.
- Run focused checks after each slice and full Debug and Release checks with Xcode 27.0 beta 5 (27A5237l) before milestone delivery. Include the existing persistence, timeline, media, output and keyboard checks. Record automated simulation results separately from the user's visual rehearsal and later physical fixture checks.
- For the user rehearsal, patch a CH 9 moving head at 001, one plug and one RGB strip. Capture two looks, place them at different times, and play them alongside projection in Test Mode. Scrub backward, try a manual override, toggle fixture blackout and Stop, then save and reopen. Verify the monitor follows each action and the saved cues remain editable.

Physical USB-DMX is scheduled for v2.03, Arduino USB serial for v2.04, and the shared song clock for v2.05. Intermediate work stays local. Use the [GitHub workflow](GITHUB_WORKFLOW.md) at the completed milestone.
