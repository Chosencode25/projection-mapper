## What changed

An optional, lock-protected diagnostic sink records scheduled submissions, skip reasons, bounded completion samples, view identity, actual pixels, CPU encoding and request-to-completion duration, optional GPU execution duration, and success. Missing GPU timestamps are unavailable rather than zero. Completion handlers retain the sink and scalar values, not the view, renderer, drawable, or command buffer. Sink release and disabled-default behavior have correctness tests.

`requestDraw` records the first pending invalidation when diagnostics are enabled; suspension clears it. Production diagnostics remain nil and drawing remains asynchronous and on demand. The benchmark uses the same `encodeScene`, normalized geometry, color, pipeline and BGRA8 format. No measured bottleneck required renderer tuning or an architecture change.

## Exact-resolution GPU workload

Each workload has three repeats, each with 30 warmups and 300 measured submissions: **900 samples per row, 9,000 total**. Textures use shared storage for separate pixel verification. Single frames run sequentially; the pair uses independent renderer queues and commits both before waiting. CPU includes render-pass/command construction and scene encoding, excluding waits/readback. GPU sum is the sum of the pair's execution durations; GPU span runs from earliest start to latest end and can include gaps. Completion wall time includes benchmark wait overhead and is not display presentation latency. Representative center/background pixels are checked outside timing.

## Native sizing, idle and lifecycle

Thirty native records cover both views across all presets, with the editor at 800×450 points and output at 800×450, 400×600 and 600×600. Drawable textures are checked against fitted bounds converted to backing pixels, within one pixel of rounding. Native scale is 2.0; a 4K preset does not imply a 4K drawable. Representative output dimensions:

| Output window points | HD / Full HD / 4K drawable | 4:3 drawable | Portrait drawable |
|---|---|---|---|
| 800×450 | 1600×900 | 1200×900 | 506×900 |
| 400×600 | 800×450 | 800×600 | 675×1200 |
| 600×600 | 1200×675 | 1200×900 | 675×1200 |

macOS marked the native test-runner windows occluded and rendering inactive. Their actual allocations prove sizing, not visible presentation. The final benchmark refreshes MTKView's cached drawable before inspecting it; an earlier measurement inspected stale cached dimensions and was superseded by the final passing run. Native timing samples are empty because the suspension guard correctly prevented rendering.

After two seconds of settling, five ten-second native harness states (editor only, both, minimized output, hidden both, closed output) each had **zero new submissions**. CPU was 0.009–0.018% of one core via `getrusage`; all views were inactive/occluded. This specifically verifies suspended idle behavior.

Separate read-only `ps` samples of the actual Release app, with diagnostics disabled, supplemented those counters. Each settled sample ran ten seconds, CPU time resolution 0.01 seconds, percentage of one core, RSS in MiB:

| Actual app state | CPU | RSS before → after |
|---|---:|---|
| hidden | 0.100% | 107.47 → 104.36 |
| both-open | 0.000% | 87.38 → 87.20 |
| minimized-output | 0.000% | 86.95 → 86.95 |
| closed-output-settled | 0.100% | 103.23 → 103.30 |

The first closed-output sample overlapped an accessibility inspection (1.0% CPU) and was excluded from idle conclusions; the settled repeat above had no overlapping UI inspection. Visible-app production counters were not instrumented, so no numeric visible frame-count claim is made. Actual-app samples are `performance/app-idle.json`; harness records are `idle.json`.

Three batches of 50 view/window open-close cycles, each with 100 preset changes, exercised **150 cycles and 15,000 changes**. Weak renderer/view references returned to nil after every autorelease pool. Peak RSS stayed **107,134,976 bytes (102.17 MiB)** across all three final batches. This is a process high-water mark, not current live allocation or a universal leak proof. Existing coordinator tests separately verify app-owned output cleanup. No measured GPU completion error occurred in the offscreen/diagnostic/synthetic workloads; occluded stress cycles do not claim GPU submission coverage.

Synthetic invalidation-to-GPU-completion uses a 640×360-point unpresented harness, explicitly overrides eligibility for each of 100 preset requests, and manually draws. p95 **4.8675 ms**, max **5.2220 ms**. It measures a synthetic request with drawable acquisition/completion overhead, not genuine OS restoration latency or visible presentation. Actual restoration was checked visually below.

## Running Release app acceptance

UI interaction began after implementation and automated measurements. The user's latest instruction explicitly authorized vital screen checks. The tested product was copied to `builds/v1.04.5/acceptance/ProjectionMapper.app` and its strict signature verified before use. The preexisting app was a clean Untitled Project and was quit before the isolated acceptance build started.

- Matching orange rectangle on black in editor and clean output, landscape 4K and Portrait; black margins and editor-only UI preserved.
- Output and editor minimize/restore shortcuts restore the rectangle without preset/resize workarounds.
- Enlarged editor covers output; Show Output restores its visible content. Output native fullscreen covers/hides the editor on another Space; Show Editor restores its rectangle after the OS transition. Escape returns output from fullscreen.
- Hide/restore the app preserves rendering. Show Editor/Show Output, sidebar/inspector toggles, and output close work.
- Default 1200×800 editor, larger native zoom, and compact native top-left tile work with portrait fitting and a scrollable inspector. The OS tile forced a smaller-than-configured-minimum layout; this was not an exact 900×600 measurement. Earlier minimum-layout evidence remains applicable.
- New Project Cancel preserves changed project and output; Discard resets it while keeping output. Editor-close Cancel and quit Cancel preserve project/output. Editor-close Discard and subsequent Show Editor return a fresh working preview with output closed.
- Final Quit Discard with output open terminates the app; read-only process inventory showed no remaining Projection Mapper process.
- Restored the original 4K preference and both panels before final quit. Temporary names were created only for acceptance checks; no existing user project was discarded.

Backing-scale transitions, physical external-display/projector reconnects, Intel and older macOS runtime checks remain unverified/deferred. No GPU utilization percentage or visible FPS was measured. These limits do not block the approved local Test Mode scope.
