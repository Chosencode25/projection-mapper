# v2.01 — Projector Output and Calibration

Status: detailed plan created and local implementation authorized October 14, 2026. Code is implemented and automatically verified in Debug/Release; local delivery is documented in [verification](V2.01_VERIFICATION.md). **Hardware acceptance remains pending.** Baseline is released v1.15.1/build 13, portable format 9. This expands the five-step outline in [V2 implementation plan](V2_IMPLEMENTATION_PLAN.md) without changing milestone order or authorizing release publication.

## Goal and scope

Send the existing clean mapped scene to one selected external display in a fullscreen output window, keep the Mac editor usable, and calibrate that output without changing layout geometry. Test Mode remains a separate, resizable rehearsal option using the same renderer, content owners and transport.

Include explicit output start/close, stable display identity, reconnect/sleep handling, display-mode diagnostics, temporary identification/calibration patterns, persistent device calibration preferences and measured timing evidence. A regular extended monitor can verify display routing; actual projector acceptance requires a projector. No hardware purchase is assumed.

Music/waveforms remain v2.02; lighting synchronization remains v2.07. Multiple outputs, edge blending, color matching, mesh/3D mapping, camera alignment and projector power/input commands remain later work. v2.01 does not change system display modes, mirroring or audio routing automatically.

## Operator behavior

1. Choose Test Window or an eligible external display in the existing output selector. Show display name, resolution, scale, reported refresh and availability reason. Require an independent extended display, external to the Mac and separate from the editor; mirrored/built-in/editor displays are unavailable for Projector Mode.
2. Selecting a display prepares a destination; it never opens output or starts playback. **Open Projector Output** creates one clean fullscreen window on that display. The editor retains controls and keyboard access. Opening output does not alter transport position or enable audio.
3. **Close Output** removes the physical window without changing mapping or transport. **Blackout** keeps output open and draws black, using the existing visual blackout behavior; it is distinct from Pause/Stop and audio mute. Escape while the physical window has focus closes physical output; provide a reachable equivalent in the editor.
4. Switching destination closes the current physical output first. The next physical destination requires explicit Open; no relocation across displays. Test Output opens only through its explicit action. v2.01 exposes one active clean output destination at a time; the editor preview remains available.
5. New Project closes physical output and preserves the existing Test Window reset behavior. Launch, project open and recovery can restore a uniquely matched destination preference but leave output closed and playback unarmed. Missing or ambiguous identities require manual selection; never match only by display name or a reused runtime ID.
6. Unplug, sleep, discovery failure, mirroring, editor relocation onto the output display or an incompatible mode change closes physical output and shows a warning in the editor. Preserve the saved preferred identity and mapping. Reconnect/wake refreshes availability; **Open Projector Output** is required again. No automatic output on the operator screen and no delayed stale reopen.
7. Display loss leaves the existing transport/audio behavior unchanged and states that playback may still be running. Provide existing Stop, Blackout and Mute actions alongside the warning. Automatic show recovery policies belong to v2.08.

## Implementation slices

### 2.01.1 — Routing and lifecycle model

- Separate remembered destination, currently eligible destination and open-output state. Model closed, opening, open, unavailable and failed states with clear reasons; only an explicit open command may transition to opening.
- Resolve a stable UUID uniquely against a fresh discovery snapshot immediately before opening. Refuse unavailable/ambiguous identity; retain explicit manual selection for displays without reliable UUIDs for the current session only.
- Add a projector coordinator with injectable display/window dependencies so routing and event sequences can be tested without visible windows. Coordinate Test Output and physical output through the session.
- Serialize lifecycle changes on the main actor; invalidate pending opens on close, destination changes, project open and discovery generation changes. Observe editor-window screen changes as well as system screen/sleep/wake notifications.
- Gate: synthetic selection, stale-open, identity replacement and loss/reconnect tests pass; existing Test selection/window tests still pass.

### 2.01.2 — Clean fullscreen output

- Build a programmatic borderless AppKit window covering the selected screen's complete frame, including negative desktop origins. Choose presentation/window-level behavior using the pinned SDK; validate menu bar/Dock/Spaces behavior on hardware before claiming clean fullscreen operation.
- Reuse `MetalSceneView`/`MetalRenderer` and the same clean scene evaluation. Keep normalized corners, masks, linked-face maps and content ownership independent of desktop points, backing pixels and Test Window presets.
- Treat current display orientation/aspect and actual drawable dimensions explicitly. Preserve normalized mapping on mode changes; expose changed aspect/resolution so the operator can recalibrate. Never rescale saved geometry silently to preserve a former physical alignment.
- Exclude editor handles, selections, reference photo, readiness messages and rendering-error text from physical output. Renderer failure closes output with an editor error rather than projecting UI diagnostics.
- Connect all scene updates, including decoder notifications, fades, calibration and identification, to the physical view. Output must not create a second video player/audio owner or transport. Minimized editor drawing can stop while the independent output continues.
- Gate: same-time offscreen pixel comparisons cover effects, images, video fixtures, masks, connected Continuous/Repeat faces, fades and blackout. Verify close releases drawables/delegates and repeat opens do not accumulate resources.

### 2.01.3 — Display changes and operator controls

- Replace deferred-output UI/readiness text with actual destination/open/error state and the explicit controls above. Keep Test Mode resolution/window behavior intact.
- On any output mode/backing/orientation change, close output and require reopening after refreshed diagnostics. This conservative first policy avoids unnoticed remapping and mixed old/new drawable state.
- Handle unplug/replug, sleep/wake, mirroring changes, editor moves, app termination and rapid repeated events idempotently. Recheck eligibility before every presentation, not just selection.
- Gate: lifecycle tests prove no window can move onto another display and no automatic resume occurs. Manual external-display checks cover focus, Escape, Spaces, Dock/menu bar, minimizing the editor and opening/closing output repeatedly.

### 2.01.4 — Calibration preferences and timing fixtures

- Reuse existing surface calibration and temporary owner identification. Add an explicit full-output identification/boundary grid with display name, dimensions and orientation only when requested; it is deliberate calibration content and is removed by Finish. Blackout overrides all patterns. Returning to Normal restores content without changing saved looks or transport.
- Store a versioned, bounded per-device/mode calibration profile in local output preferences: stable display UUID, mode dimensions/refresh, measured delay, intended compensation value and measurement notes. Keep active patterns, output-open state and transient measurements runtime-only. Display-mode changes flag the profile for remeasurement; absent/ambiguous identities never silently inherit another profile.
- Preserve portable format 9 unless implementation establishes a genuine project-data requirement. Device profiles belong to the current Mac, not portable geometry; malformed/older preferences fall back safely. Record this decision and tests before introducing any package migration.
- Provide a finite visual compensation setting in milliseconds, default zero, bounded to -500…+500 ms. Define positive as evaluating visual content later on the authoritative timeline to compensate a late projector image; negative evaluates earlier. In v2.01 store/display the setting as **reserved for v2.02 music synchronization**, without altering existing video/audio playback. v2.02 must apply it once with explicit seek/loop boundaries; saved measurement is not proof of compensated sync.
- Supply project-owned grid and frame-number/flash fixtures with known frame cadence. Target initial measurement at 1920×1080/60 Hz where the hardware supports it; otherwise record the actual mode/cadence before testing. Distinguish app render/submission cadence from optical projector latency; use a sufficiently fast camera or suitable sensor/reference for physical delay and record uncertainty. Without measurement equipment, optical timing stays pending.
- Report steady offset, frame interval variation/jitter, dropped/repeated frames and cumulative drift separately. Aim for at most one output frame of residual alignment after later music compensation where feasible; no music-sync acceptance claim in v2.01. Record observed limits rather than infer latency from reported refresh alone.
- Gate: profile validation/identity/mode invalidation and temporary-pattern restoration tests pass; measured fixtures and actual equipment/modes are documented.

## Acceptance checklist and completion labels

| Check | Evidence required |
|---|---|
| Destination safety | Synthetic missing/ambiguous/reused identity, mirrored/built-in/editor rejection, negative-origin and stale-event tests |
| Shared output | Offscreen same-time scene checks; one content/video/audio owner across views; no duplicated playback |
| Test Mode preserved | Existing selection, resolution, resize, close/reopen and rendering-availability regressions |
| Physical presentation | User confirms selected external display only, fullscreen clean scene, accessible editor/close/blackout and Spaces/focus behavior |
| Mapping/calibration | Projector checks corners, boundaries, masks, object joins, orientation, identification and pattern restoration |
| Recovery | Actual unplug/replug, sleep/wake, mode/mirroring changes and relaunch leave output closed; explicit reopen restores intended display |
| Persistence | V1 package/media/geometry preservation and safe local calibration-profile validation; no autoplay or auto-open |
| Performance/timing | Recorded workload, render cadence and available optical measurements; unsupported modes/devices remain unverified |
| Delivery | Tested local binary/archive identity and accurate verification/progress notes |

Use **implemented and automatically verified; physical acceptance pending** when code/headless checks are complete but equipment or user checks are unavailable. Mark **projector operation accepted** only after the actual projector checklist passes and record remaining timing limits separately. External-monitor acceptance does not substitute for projector latency/alignment acceptance. Independent v2.02–v2.06 work may proceed in Test Mode without converting pending hardware checks into passes.

Routine visual checks are user-performed. Provide the checklist with the local build; use no screen control unless investigating a specific expected bug under the project preference. Record reported visual acceptance separately from automated results.
