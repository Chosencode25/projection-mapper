# v1.11.1 — Appearance, crop and flips

October 5, 2026. First slice of [v1.11](V1.11_PLAN.md), implemented locally after v1.10 source backup **55d242c** was successfully pushed to GitHub main. No v1.11.1 commit/push/tag/release. Bundle stays **1.10/build 7** during intermediate development. Xcode 27.0 beta 5 (27A5237l) reverified; deployment target macOS 15.0.

## Implemented

- Opacity 0–100%, brightness 0–200%, bounded source crop and horizontal/vertical flips in the inspector. Brightness multiplies evaluated RGB and clips to white, retaining alpha; opacity multiplies alpha. Existing straight-alpha compositing is shared by preview/output; opacity zero skips contribution and animation demand.
- Object-owned shared appearance with inherited member-face controls and a clearly labelled full face override. Enabling copies effective settings; disabling returns to inheritance. Overrides replace the object's complete appearance value, so an overridden face retains its own crop/flip as well as opacity/brightness when the object changes. Join diagnostics flag crop/flip or appearance differences.
- Sampling uses crop × flip × input map after the inverse homography. Shared controls preserve matching joined coordinates; Repeat repeats the cropped/flipped full canvas. Output corners, input regions, membership, generator colors/settings, presets and playback remain separate.
- Grouping adopts the frontmost checked face's effective appearance and returns members to inheritance. Attach adopts destination object settings. Detach/ungroup bake effective appearance into standalone controls; object/face duplicates retain appearance and overrides with independent IDs.
- Schema 3 packages persist appearance, including overrides, in normal saves and recovery. Schema 1/2 migrations supply defaults and preserve supported layout/content/IDs. Invalid/nonfinite values and orphan standalone overrides are rejected before replacing state. New values participate in saved baselines and autosave.

This slice does not implement locks, group movement, scoped resets, looks/palettes or master fade/blackout; they remain the next two slices. Generator presets remain effect/color presets and do not change appearance.

## User visual checks

No screen control was used. User acceptance is pending:

1. Overlap two faces, change the upper face's opacity and brightness, and compare the editor and Test Window. Zero opacity should reveal the lower face; brightness zero should turn an opaque face black.
2. Group faces, inspect the object, and try crop/flips. Enable one face's override, adjust it, then disable it to return to shared controls. Output corners should remain fixed.
3. Save/reopen the edited project. Appearance/overrides should return, with animation paused. Try a copy of an earlier v1.10 project to confirm default controls.

Schema 3 files require this preview or later; the backed-up v1.10 app supports schema 2 and will reject a newer file. Keep earlier project copies when using the old app. Intel/older macOS runtime and physical projector output remain unverified/deferred.
